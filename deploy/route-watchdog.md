# Independent routing custody

`gateway/route-watchdog.ts` runs separately from the application, its Containers and the deployment runner. One account-wide SQLite Durable Object serializes this controller's operation, signed plan, complete baseline, write-ahead intents and local-controller journal. A duplicate reservation returns the original receipt; a different operation cannot take an active or unresolved lease. Bound histories are retained when the next operation starts. Actual proof that other consequential route writers are stopped remains required for exclusive operational ownership.

The control service has no business-host route attached or customer-data access. Its exact workers.dev origin requires a private control secret. A separate narrow provider token grants Worker-route access to only the reviewed zones; it grants no DNS, SQL, customer messaging or listing-publication authority. Production binding requires distinct configured owner/controller Ed25519 keys, exact plan signatures, a fresh independent complete staging report and unchanged provider routes. Blank keys keep production binding unavailable. This custody signature check supplements the complete unchanged promotion gate in the CLI.

Only the service performs route mutations. It stores the exact intent before contacting Cloudflare; a missing acknowledgement fences replay. Its persisted alarm survives runner disappearance. Recovery processes one route or check per wake, restores original route IDs and omitted-script bypasses, removes only recorded candidate-created bindings, and preserves foreign changes. Exact baseline route readback and strict Host/SNI probes of both original WordPress hosts are required for a restored production state. It never restores a database snapshot or discards accepted writes.

Origin verification runs in one isolated native Node Container, using the same `probeLegacyOrigin` implementation as the operator CLI. The production Workers edge cannot honor the required custom SNI for a connection pinned to the original IP; the unsupported socket implementation is removed. The probe image has no application, database, customer, email or provider credentials. It accepts only the two original hosts, verifies the exact IP and TLS server name, follows no redirects, and bounds the actual nonempty HTTP200 body. Its separate immutable image/source and observed actor are retained with the controller proof. It has no role in the common application image or its three runtime roles.

Alarms remain armed after the first restoration and sweep for late provider effects. A restored bound lease stays fenced until separately signed owner/controller release, repeated clean observations and another fresh baseline read. A controller-signed complete production report with the exact operation, source, image, deployed gateway, full applied state and artifact bindings is required to accept the operation and disarm. A local status label or journal upload cannot do that. Local acceptance remains `awaiting_watchdog_acceptance` until the independent acknowledgement is verified.

Build `deploy/OriginProbe.Dockerfile` for linux/amd64 with `SOURCE_COMMIT` set to its actual committed source. Push the isolated image with the pinned gateway Wrangler and retain its provider registry digest and build provenance. Generate a configuration with `node scripts/watchdog-config.mjs <controller-sha> <private-config.json> <immutable-probe-image> [probe-source-sha]`. Mutable tags, another account or another image repository are rejected. Validate that configuration with the pinned gateway Wrangler before private provisioning. Mount `WATCHDOG_CONTROL_SECRET` and the reviewed `WATCHDOG_ROUTE_TOKEN` as secrets, never config variables. Public key custody and actual provider deployment/version readback remain separate evidence. Uploading this service is not an application deployment or production acceptance.

Before approving a cutover plan, reserve the operation through `node scripts/production-watchdog.mjs reserve <private-scope.json> <private-receipt.json>` with `PRODUCTION_WATCHDOG_CONTROL_SECRET`. The scope contains the exact operation UUID, lease UUID, source commit, image digest, baseline SHA and source-zone IDs. Bind the actual receipt hash and expiry into the ownership/recovery artifacts before owner/controller plan approval. The production routing CLI verifies the retained remote receipt, binds the signed plan and sends its provider writes and journals through this service. The local Cloudflare credential is used for independent reads; there is no direct-write fallback.

The authenticated rehearsal endpoint generates only `watchdog-rehearsal.makler-realty.com/<operation-uuid>/*`, uses this service as its candidate script and restores the actual original route inventory. It cannot accept a caller-chosen business host or Worker. Its short timeout and optional late-write fault are explicitly isolated provider exercises. Rehearsal receipts set business-host coverage false and cannot become production custody or launch approval. Close the rehearsal only after repeated exact baseline observations, then remove any separately journaled canary seed and revoke temporary credentials. Keep the raw provider, process-termination and independent observer receipts.

Current source and local fixtures do not prove hosted alarm execution, exclusive operational access, independent signing custody, public RU authority, source parity, runtime/customer delivery or an actual production recovery drill. Retain the promotion hold until each has real exact-release evidence.

The implementation follows the provider's [Durable Object alarm contract](https://developers.cloudflare.com/durable-objects/api/alarms/), [concurrency rules](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/), [Container runtime](https://developers.cloudflare.com/containers/get-started/) and [route update API](https://developers.cloudflare.com/api/resources/workers/subresources/routes/methods/update/). The [runtime source](https://github.com/cloudflare/workerd/blob/main/src/workerd/api/sockets.c%2B%2B) records the unsupported custom-SNI option; the separate native probe preserves strict verification.
