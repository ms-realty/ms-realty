## 1. W03 handover · receiver side (Никол)

Command family: `handoverTask` (`work/handover.ts`). Today it supports `request`, `accept` and `cancel`. The W03 seams it needs:

- **A. Receiver accept.** Accept with the receiver's own `nextStep` (text) and `reviewAt` (future time, no default). It is bound to the request version, and only the receiver may call it.
- **B. Receiver decline.** Decline with a required `reason`. Only the receiver may call it.
- **C. Sender cancel.** This is the existing `cancel`. It must stay distinct from decline.

Until A succeeds, ownership and coverage stay with the sender.

## 3. P12 · Inquiry receipt names the saved property

Read: `readInquiryReceipt` → receipt DTO. Per listing item (`listing`, or each item of `selectedListings` in the saved order): `{ reference, title | null, locale | null, sourceUrl | null, publicNow: true | false | null }`.

- `title` is the name saved at submission and is never re-read from today's listing.
- `publicNow` is read from the current publication only. No other live facts are shown: no price, area or availability.

The receipt header, number, owner line and «Какво следва» row are unchanged (`server.receipt.inquiryIntake.accepted.*`). The old price/area facts line is hidden because the DTO does not carry it.

Row rendering (one row per item, single and multi lists can mix):

| Item state | Row content | Link (Quiet button) | Copy keys |
|---|---|---|---|
| `publicNow = true` | saved title; «№ {reference}» | «Вижте имота» → `sourceUrl`, or the detail route by reference when `sourceUrl` is null | `public.inquiry.receipt.listingName` (title as saved), `.listingReference`, `.viewListing` |
| `publicNow = false` | saved title; «№ {reference}»; plain line «Тази обява вече не е активна.» | no link to the listing; «Вижте подобни имоти» → search recovery (P22) | `.listingNotPublic`, `.viewSimilar` |
| `publicNow = null` | saved title; «№ {reference}»; no availability line | no promise that the listing opens; «Потърсете имот № {reference}» → search (P02) | `.searchByReference` |
| `title = null` (any `publicNow`) | «Имот № {reference}»; «Името на имота не е записано в това запитване.»; plus the line or link of its `publicNow` value | as above | `.listingReferenceOnly`, `.noSavedName` |

Every receipt carries a block heading and a caption under the rows:

- Heading: «Имотът в запитването», or «Имотите в запитването · {count}» for several (`public.inquiry.receipt.listingsHeading`).
- Caption: «Името е записано при изпращането на {submittedAt}. Ако обявата се промени по-късно, тук остава същото.» (`.savedNameNote`). It reads «Номерът е записан при изпращането на {submittedAt}.» when no name was saved.

## 4. Open server questions

1. Handover receipts show a human reference («потвърждение № 0418»). Will `handoverTask` readbacks return one, or should the line show only the person and the time?
2. Does the receiver view of a sender cancel (O23HRX) have its own readback state, or does the receiver read `cancelled` with the acting person? The copy deck words `cancelled` for the sender only.
3. Should the absence window on O23HR («отсъства от 12 до 16 октомври») come from the absence record linked to the handover request? If that link is not stored, the line is dropped.
4. P12: is `selectedListings` returned in the saved order of selection, and is `listing` always null when the inquiry was about several properties?
5. P12VIEW: does the receipt DTO carry the inquiry purpose (viewing request) so the header can read «Заявката за оглед е получена»? The requested time is not shown until the DTO carries it.
6. P12: `{submittedAt}` in the caption assumes the receipt returns the saved acceptance time with its time zone.
