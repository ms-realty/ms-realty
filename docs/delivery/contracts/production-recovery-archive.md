# R08 / AT64 recovery archive contract

Package A defines the wire format for one source epoch, one recovery point and the journal window after its snapshot. A valid result describes relationships among supplied records. All results require quarantine. Live copy verification, source fencing, restore, Ivan's review and any reopening decision have separate evidence and authority. [Architecture §17.3](../../architecture.md#173-backups-and-restore) · [ADR 0006](../../adr/0006-cloudflare-recovery.md)

## Inspect a packet

Call `inspectRecoveryArchive(expected, packet)` in a Node environment. Both inputs are strict schemas. A conflict throws. A truthful missing copy, authority read or closed barrier produces a result with `currentness: "unknown"`. The caller obtains the expected release context and point digest independently of the proposed restore. Unknown values use the explicit nullable fields. [Contract and exported types](../../../src/domain/recovery-archive.ts)

| Input            | Required binding                                                                                                                                                                                                                                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Expected context | Product, environment, exact source SHA, release and schema digests, reviewed writer registry, source database lineage and instance, writer epoch, archive namespace, both destination identities and encryption profile                                                                                                      |
| Expected point   | Hash of the complete canonical point index, obtained from the trusted point selection. The index identifies the snapshot, its journal anchor and encrypted database dump, table manifest, object manifest and configuration manifest.                                                                                        |
| Source journal   | One envelope per committed transaction, with sequence, predecessor, source-scoped transaction reference and typed effect references. Each entry binds the context, effect kind, subject digest and payload digest. Its encrypted payload must contain resolvable typed restrictive effects.                                  |
| Copy evidence    | For each point component and archived segment, per-destination conditional-create and actual ciphertext-readback receipt hashes, location, byte length and hash. A missing receipt is null. The opaque destination references must resolve to the approved EU archive and an encrypted copy outside the application account. |
| Watermark        | Exact generation, predecessor, committed head, contiguous prefix at each destination, and digest of the complete copy-receipt set. A separate current authority read pins the watermark and optional barrier digests to the requested restore ID, isolated destination instance and challenge.                               |
| Closed barrier   | Exact source context, point, generation and final committed head, with references to the write-fence receipt, accepted-write ledger and writer-coverage evidence.                                                                                                                                                            |

The copy key in this format is `<archiveNamespace>/sha256/<ciphertext-sha256>`. A retried upload must reuse the prepared ciphertext and conditional-create identity. The outside copy can map the logical key to its approved storage location. The encryption profile identifies the approved scheme and recipient fingerprints. Private keys stay in operator custody.

Changes of release or epoch require a separately verified transition from the previous anchor. Treat continuity across such a boundary as unresolved until a transition contract exists.

The source writer must hold the same transactional fence through outer commit that the epoch closer takes exclusively. Commit the business change, operation outcome, journal envelope and immutable archive intent together. A nested `runOperation` can return before its caller's outer transaction commits. An archive worker reads visible committed rows from its own connection. A revocation takes effect locally even while archive replication is down. Persist its original receipt and surface pending replication separately. [Operation transactions](../../../src/server/operations.ts) · [Existing local privacy chain](../../../src/server/privacy/safety-ledger.ts)

The inspector starts each destination at the independently pinned snapshot anchor only if it has receipts for every point component. It checks each entry and segment in order, hashes its exact canonical plaintext and compares every supplied copy's ciphertext identity and size. A destination with a missing segment can only advance through the previous contiguous prefix. A later copy leaves that gap open. The common archive prefix is the lower position of the two destinations, or null if either lacks the point.

A source whose epoch is open, lost or unknown can have committed another revocation after the latest copied prefix. Its currentness stays unknown even when both destinations reach every supplied entry. A closed barrier can yield `closed_barrier_bound` only with complete prefixes, matching independently pinned watermark/barrier, and no reported unresolved writer or object. The result always carries `evidenceClass: "structural_only"` and `quarantine: "required"`. A fabricated receipt digest has the same shape as a genuine one. The future adapter must authenticate its origin, fetch and verify the raw bytes, enforce freshness and compare-and-swap against the actual predecessor. The inspector has no authority-read, clock, signing, storage or reopening capability.

The point index pins encrypted component files. Their contents require separate verifiers. Database dump, canonical row hashes, schema/migrations, object references and journal/accepted-write anchors must come from one consistent snapshot. The object manifest proves every required reference against recoverable bytes. The configuration manifest indexes recoverable nonsecret configuration, image digests, policy/identity mappings, queue state and external secret-custody references. A closed epoch cannot make an old snapshot fresh or turn an unresolved file into a recoverable one.
