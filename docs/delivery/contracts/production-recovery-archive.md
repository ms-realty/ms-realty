# R08 / AT64 recovery archive contract

Package A defines the wire format for one source epoch, one recovery point and the journal window after its snapshot. A valid result describes relationships among supplied records. All results require quarantine. Live copy verification, source fencing, restore, Ivan's review and any reopening decision have separate evidence and authority. [Architecture §17.3](../../architecture.md#173-backups-and-restore) · [ADR 0006](../../adr/0006-cloudflare-recovery.md)

## Inspect a packet

Call `inspectRecoveryArchive(expected, packet)` in a Node environment. Both inputs are strict schemas. A conflict throws. A truthful missing copy, authority read or closed barrier produces a result with `currentness: "unknown"`. The caller obtains the expected release context and point digest independently of the proposed restore. Unknown values use the explicit nullable fields. [Contract and exported types](../../../src/domain/recovery-archive.ts)

| Input            | Required binding                                                                                                                                                                                                                                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Expected context | Product, environment, exact source SHA, release and schema digests, reviewed writer registry, source database lineage and instance, writer epoch, archive namespace, both destination identities and encryption profile                                                                                                                                 |
| Expected point   | Hash of the complete canonical point index, obtained from the trusted point selection. The index identifies the snapshot, its journal anchor and encrypted database dump, table manifest, object manifest and configuration manifest.                                                                                                                   |
| Source journal   | One envelope per committed transaction, with sequence, predecessor, source-scoped transaction reference and typed effect references. Each entry binds the context, effect kind, subject digest and payload digest. Each restrictive payload digest identifies a separate encrypted replay object.                                                       |
| Copy evidence    | For each point component, archived segment and restrictive replay object, per-destination conditional-create and actual ciphertext-readback receipt hashes, location, byte length and hash. A missing receipt is null. The opaque destination references must resolve to the approved EU archive and an encrypted copy outside the application account. |
| Watermark        | Exact generation, predecessor, committed head, contiguous prefix at each destination, and digest of the complete copy-receipt set. A separate current authority read pins the watermark and optional barrier digests to the requested restore ID, isolated destination instance and challenge.                                                          |
| Closed barrier   | Exact source context, point, generation and final committed head, with references to the write-fence receipt, accepted-write ledger and writer-coverage evidence.                                                                                                                                                                                       |

The copy key in this format is `<archiveNamespace>/sha256/<ciphertext-sha256>`. A retried upload must reuse the prepared ciphertext and conditional-create identity. The outside copy can map the logical key to its approved storage location. The encryption profile identifies the approved scheme and recipient fingerprints. Private keys stay in operator custody.

The source codec writes the complete scoped restrictive command inside the encrypted replay object, including the identifiers and decision needed to apply a denial after the snapshot. The public packet holds only the kind, subject digest, measured byte identities and per-destination receipt references. When authorized to restore, the private adapter must decrypt the pinned object, recompute its plaintext digest, decode the exact source schema, verify its kind and subject, and apply the restrictive operation under quarantine. An unknown codec, missing target context or malformed command keeps the restore closed. Accepted-operation and external-outcome digests identify receipts for separate reconciliation. They give no authority to reconstruct a customer command or resend an external action.

One registry uses each raw SHA-256 as its key across the whole packet. It records the artifact’s role, exact scope and known byte length. A hash-only reference can acquire a byte length from a matching object later in the same packet. Every measured length must agree. Each named point component, journal segment, scoped effect body, ciphertext, storage receipt and source-fence artifact has a distinct role or scope. The same bytes cannot gain another role by being wrapped in a new encryption envelope. Context, source metadata, journal heads, subject commitments, copy sets, watermarks and barriers also register their known identities. Repeated references to the same scoped payload or same destination receipt are valid when their semantics and measured lengths agree.

The registry can reject incompatible claims already visible in the packet. For previously unseen bytes, an authorized private reader must authenticate their source, decrypt the object, validate the approved codec, verify its subject and check the applicable policy and human authority for the restrictive action. Structural consistency leaves the actual plaintext semantics, lawfulness and authorization unverified.

Changes of release or epoch require a separately verified transition from the previous anchor. Treat continuity across such a boundary as unresolved until a transition contract exists.

The source writer must hold the same transactional fence through outer commit that the epoch closer takes exclusively. Commit the business change, operation outcome, journal envelope and immutable archive intent together. A nested `runOperation` can return before its caller's outer transaction commits. An archive worker reads visible committed rows from its own connection. A revocation takes effect locally even while archive replication is down. Persist its original receipt and surface pending replication separately. [Operation transactions](../../../src/server/operations.ts) · [Existing local privacy chain](../../../src/server/privacy/safety-ledger.ts)

The inspector starts each destination at the independently pinned snapshot anchor only if it has receipts for every point component. It checks each entry and segment in order, hashes its exact canonical plaintext and compares every supplied copy's ciphertext identity and size. A destination with a missing segment can only advance through the previous contiguous prefix. Each version 2 watermark binds the segment archive and its replay-object records. For every access revocation, privacy restriction, deletion decision, consent withdrawal or publication withdrawal, the segment must reference a replay object of the same kind, subject and plaintext SHA-256. Both the segment and all its restrictive payloads must have verified copies at a destination to advance that destination. An empty replay-object list or a null destination receipt records missing data. A later copy leaves the gap open. The common archive prefix is the lower position of the two destinations, or null if either lacks the point.

A source whose epoch is open, lost or unknown can have committed another revocation after the latest copied prefix. Its currentness stays unknown even when both destinations reach every supplied entry. A closed barrier can yield `closed_barrier_bound` only with complete prefixes, matching independently pinned watermark/barrier, and no reported unresolved writer or object. The result always carries `evidenceClass: "structural_only"` and `quarantine: "required"`. A fabricated receipt digest has the same shape as a genuine one. The future adapter must authenticate its origin, fetch and verify the raw bytes, enforce freshness and compare-and-swap against the actual predecessor. The inspector has no authority-read, clock, signing, storage or reopening capability.

The point index pins encrypted component files. Their contents require separate verifiers. Database dump, canonical row hashes, schema/migrations, object references and journal/accepted-write anchors must come from one consistent snapshot. The object manifest proves every required reference against recoverable bytes. The configuration manifest indexes recoverable nonsecret configuration, image digests, policy/identity mappings, queue state and external secret-custody references. A closed epoch cannot make an old snapshot fresh or turn an unresolved file into a recoverable one.

Package B adds a local transactional journal with an **inactive** source singleton. It supplies no application, worker, CLI or configuration admission path. Its only declared writer seam is the opt-in `runOperation` receipt boundary; coverage remains `incomplete`, archive acknowledgment remains `unconfigured`, and currentness remains `unknown`. The restrictive codecs have no qualified domain replay adapter. [Journal](../../../src/server/recovery/journal.ts) · [Source fence](../../../src/server/recovery/write-fence.ts)

`withRecoveryTransaction` can own a new outer transaction only outside a recovery callback scope. Inside a managed callback, a nested writer must use that callback's exact current transaction through a managed savepoint. Both append APIs bind ownership checks to the actual asynchronous calling scope. A caught rejection involving an ancestor, expired handle, pool or raw savepoint poisons that scope. A genuinely rolled-back child contains its failure and leaves a healthy parent usable; a success-looking callback return cannot clear failure. Misuse of a known foreign owned handle also poisons its live owner, because direct writes through that handle may belong to another transaction.

A callback stops accepting appends before final flushing begins. Detached callbacks cannot append or start another root after their scope ends. If an owned ancestor is still inside its managed callback or final flush, failure propagates to that ancestor. After the wrapper hands control to the driver's COMMIT, stale calls still reject without appending or starting a root; they cannot retroactively cancel that completed callback. Callers must await all domain and journal work before returning. Ordinary `runOperation` calls outside every recovery scope and without explicit admission retain their existing behavior and make no participation claim. These APIs do not sandbox arbitrary SQL on retained handles: writes outside a managed callback's lifetime, unknown external transactions and uninstrumented writers still prevent complete-coverage qualification.

The source fence precedes operation/domain locks and remains held through the actual outer commit. Only that outer owner flushes an envelope; successful savepoint release is provisional. Accepted-operation references come from persisted succeeded receipts, read and rechecked under `FOR SHARE` before the journal-head lock. That receipt lock survives both a wait for the head and the actual outer COMMIT. It establishes the succeeded receipt binding at commit; it does not make the existing operations table immutable against later uninstrumented updates. Such updates remain outside coverage, while the journal retains the committed observation.

The local closer waits for covered outer transactions and binds their final committed head. Its result is expressly not this contract's independently authenticated closed barrier: unresolved writers remain, and it returns no archive barrier or recovery permission. No production completeness follows from the new tables or passing disposable-database tests.

## Bounded C1 grant-revocation source

C1 adds one dormant producer: `revokeStaffGrant` and the actual grant/session denials it commits. Its optional fourth argument is server-selected recovery admission, separate from parsed command input. It reaches the existing `runOperation` fence before operation or staff-management locks. No route, configuration, environment flag, worker or activation adapter supplies it. Unadmitted calls retain their normal result and create no recovery rows, including when submitted fields resemble admission. An already-owned scope must pass the matching explicit C1 context; omission or mismatch fails and poisons the calling scope instead of silently producing accepted-only history. [Command](../../../src/server/auth/grants.ts) · [C1 integration evidence](../../../src/server/auth/grants-recovery.int.test.ts)

The additive v2 payload supports only `grant` and `session` denials. It retains the actual locked grant's observed revision and returned post-update revision. Sessions have no version: their targets contain only the returned session UUID, principal UUID and actual session kind. The target principal's kind comes from its database row, even when this historically named command accepts a client-backed grant. The session delegate executes the same bulk-update predicate as the existing count API and returns only safe identities. The producer sorts the changed session set by UUID, rejects duplicates and contradictory bindings, and excludes previously revoked and unrelated sessions. [Codec and row binding](../../../src/server/recovery/access-restrictions.ts) · [Codec evidence](../../../src/server/recovery/access-restrictions.test.ts)

Each denial retains the canonical `grant_revocation_server_observation_v2` body. Its `decisionId` is the actual `recordAudit` UUID; the body binds the genuine operation UUID/request hash, staff actor, checked session identity, target principal, grant scope and revisions, evaluated capabilities, fixed `grant_revoked` reason and exact changed sessions. The check markers are emitted after the command's actual in-transaction live/fresh-session, passkey-minimum, scoped-authority and remaining-manager checks. Before staging, the journal validates the observation against the persisted audit, in-progress operation and actual target rows. No bearer token, token hash, passkey material, arbitrary reason note or customer content is copied to recovery payloads.

`authorizationDigest` is specifically SHA-256 of canonical JSON `["access-grant-revocation-observation-v2", decision]`. It is an **integrity-bound observed server decision/audit projection**, not a signed permission approval, independent permission proof or reconstruction of unobserved granting rows. The decoder retains and rehashes this body, rejects mismatched decisions/targets, and verifies canonical bytes and context. The envelope payload is `["recovery-access-restriction-v2", contextDigest, restriction]`; its subject commitment uses `access-restriction-subject-v2`. The existing v1 codec, domain separators and canonical bytes remain unchanged and retain an independent fixed-byte vector. [v1 compatibility evidence](../../../src/server/recovery/journal.test.ts)

Every append is awaited in the same managed domain savepoint, with the final envelope and succeeded receipt reference committed only by the true outer transaction. Local append failure rolls back domain changes; catching the failure cannot turn the scope into success. Ordinary domain `AppError` outcomes retain only their existing failed operation receipt after savepoint rollback, without safety payloads or accepted references. C1 retains Package B's raw-handle, ancestor, foreign-pool, detached-callback and actual-COMMIT limitations. Its tests cover actual grant/session readers, target kinds, replay and current authority, failed receipt isolation, meaningful database failure positions, a deferred COMMIT failure, nested rollback/sibling success and both fence orders using observed PostgreSQL blocking. These are local source checks, not operational release evidence.

Replay execution remains unimplemented. Decoding these two restrictive targets does not demonstrate production restore, idempotent restoration, target compatibility or recovery currentness. A future replay executor must preserve quarantine for missing or newer incompatible targets, reject ID/principal mismatches, tolerate an already-applied denial and never create or revive a grant/session. C1 does not instrument grant creation, offboarding, direct invitations, credentials, general sessions, Case participation or document cancellation. Archive bytes, storage, watermark/backend authority, baseline/epoch continuity and actual restore remain unresolved. The inventory still contains 77 candidate modules and 214 candidate scopes; this single command is no claim of complete auth, Phase C or R08 qualification.
